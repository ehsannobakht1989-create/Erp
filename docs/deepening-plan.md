## Appendix A — PROMPT 11 (Deepen ONE module)

```
Branch: module/<ID>-deep
Goal: raise module <ID> from skeleton to depth-gate PASS (score >= 80, all categories >= 60). The script decides, not you.

1. Read AGENTS.md, docs/module-pattern.md, docs/ui-kit.md, docs/core-api.md, specs/<ID>.md, docs/depth-status.md (the "missing" list for <ID>), Contracts of every module in its requires/optional/consumes, and modules/item-master (reference for structure).
2. Work in these slices. After EACH slice: run php tools/test.php and php tools/depth-check.php <ID>, commit with message "<ID>: slice N ...".
   Slice 1 — Schema: every entity in the spec as tables with proper keys/indexes/constraints, company_id, timestamps, soft delete where relevant; repositories.
   Slice 2 — Domain services: implement EVERY rule in the spec "Rules" section (validation, state transitions, calculations, locking, numbering). One named test per rule (happy path + at least one failure path).
   Slice 3 — Workflows & events: register workflows/definitions, emit every "Events out" event with the documented payload, implement real handlers for every "Events in" (idempotent), outbox-safe.
   Slice 4 — Contract: implement the full Service contract interface(s) with real logic and tests (including guards for optional providers).
   Slice 5 — API: dedicated endpoints per entity and per business action (not only generic CRUD): filters, pagination, bulk actions, imports/exports where the spec lists them, permission guards on every route, audit on every mutation, OpenAPI updated.
   Slice 6 — UI: for each main entity list + form + detail pages, status chips/actions per workflow, reports/screens listed in the spec, i18n fa keys, RTL, mocks matching OpenAPI, permissions in routes.
   Slice 7 — AI block: tools (read-only) and proposals per spec; tests with provider=off and fake provider; redaction.
3. Do NOT stop while the gate reports missing items. Keep iterating on the script's "missing" list until it passes. Never edit the gate to pass; never add placeholder code to satisfy a metric.
4. Budget: up to 80 files for this module. Keep files focused.
5. Finish: run tools/budget.sh, validate-manifests, tests, depth-check. Set "status":"done" ONLY if the script allows it. Open ONE PR. In the PR description paste the depth-check output for <ID> and list anything deliberately deferred.
```
