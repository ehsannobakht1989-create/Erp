# mrp — Material requirements planning (L4; requires bom, inventory; optional purchase-order, work-order, sales, mps, reorder-point, routing)

**Entities** MrpParam per item/plant{make_or_buy,lead_time_days(purchase/production),lot_sizing[lot_for_lot|fixed|min_max_multiple|eoq|period],lot_size,min_qty,multiple,safety_stock,safety_time_days,yield_pct,planning_time_fence,planner_id,low_level_code,planning_enabled}; MrpRun{scope,mode[regenerative|net_change],horizon,status[queued|running|completed|failed],started,finished,stats}; PlannedOrder{item,type[purchase|production|transfer],qty,start,due,status[proposed|firmed|released|cancelled],pegging}; MrpMessage{item,order_ref,action[expedite|defer|cancel|increase|decrease|release],reason}; Pegging{demand_ref→supply_ref}.
**Rules** low-level code computation; per level: gross requirement (independent demand from sales backlog/MPS/forecast, dependent from parent planned orders via BomService::explode with scrap/yield) minus on-hand available (InventoryService, excluding quarantine, including safety stock), scheduled receipts (open POs from PurchaseOrderService, open WOs from WorkOrderService, transfers) → net requirement → lot sizing → offset by lead time using calendars; substitutes optional; respect firmed orders & time fences; pegging maintained; runs are chunked by level/item batches with resume tokens (queued via outbox, executed in `events:work` slices of N items); optional Python accelerator for very large item counts (setting); simulation runs don't write planned orders; exceptions: past-due, no-BOM, no-lead-time, over-capacity (if routing available).
**Events out** mrp.run.completed, mrp.planned_order.firmed{→WO draft}, mrp.requisition.suggested{→purchase-request draft}, mrp.message.created. **In** inventory.*, purchase-order.po.*, work-order.wo.*, sales.order.*, mps.plan.released, reorder-point.policy.changed.
**Service contract** MrpService: runStatus(id), plannedOrders(filter), pegging(item,date), firm(plannedOrderId), requirements(item,range), mrpParams(item).
**Permissions** mrp.run.execute|view, mrp.planned-order.view|firm|release|delete, mrp.param.manage, mrp.message.act.
**Screens** run console (start/monitor/resume), planner workbench (stock/requirements time-phased per item, pegging drill-down), planned orders grid (bulk firm → create WO/PR), message list (expedite/cancel suggestions), parameter mass editor/import, exception dashboard, simulation compare.
**AI** anomaly (suspicious params, e.g. lead time outliers), autofill (suggest lot size/safety stock from history, proposal), summarize run results, nl_report ("which materials will short next 3 weeks?").
**Iran** long import lead times & customs buffer fields (safety_time), supplier-specific lead times from purchase history.
