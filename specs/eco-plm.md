# eco-plm — Engineering change & product lifecycle (L5; requires bom, routing; optional item-master, document-mgmt, work-order, quality-inspection)

**Entities** ChangeRequest(ECR){title,reason,requester,source[customer|quality|cost|compliance|supplier],status[new|review|approved|rejected|converted]}; ChangeOrder(ECO){number,type[engineering|manufacturing|document|deviation|waiver],impacted_items[],impacted_boms[],impacted_routings[],impacted_documents[],effectivity{type[date|lot|serial|work_order],value},disposition_of_stock{use|rework|scrap|return},status[draft|review|approved|implementing|released|closed|cancelled]}; ChangeTask{owner,description,due,status}; ReviewerSignoff{discipline,user,decision,comment}; ItemLifecycle{item,state[prototype|pilot|production|phase_out|obsolete]}; DocumentRevision link.
**Rules** impact analysis uses BomService::whereUsed and routing/doc links; approval workflow with parallel discipline reviewers (engineering, quality, production, purchasing, finance as configured); release creates NEW BOM/routing revisions (via their services/events, never direct table writes) with effectivity; open work orders handled per policy (apply, ignore, require decision); stock/WIP disposition tasks generated; deviation/waiver has expiry; audit trail immutable; ECO closes when all tasks done.
**Events out** eco-plm.change.requested|approved|released|closed. **In** bom.bom.approved, routing.routing.approved, work-order.wo.created (apply check).
**Service contract** EcoService: pendingChanges(item), effectiveRevision(item,context), impact(itemIds), lifecycle(item).
**Permissions** eco-plm.ecr.view|create|approve, eco-plm.eco.view|create|approve|release|cancel, eco-plm.lifecycle.manage.
**Screens** ECR/ECO lists & forms, impact analysis tree, reviewer matrix, task board, revision timeline per item, effectivity setup, lifecycle board.
**AI** summarize change impact, autofill (draft ECO from ECR text), anomaly (changes that repeatedly affect same items), next_action.
